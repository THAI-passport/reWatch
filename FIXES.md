## Open
- t900-c900: profile `c900-nordic` and PROTOCOL.md use Nordic UART UUID `6E400001-B5A9-...` while Nordic's published NUS base is `6E400001-B5A3-...CA9E` [W, Nordic docs]. Settle with the HW-2 GATT dump (tools/ble_survey.py), then fix models.py, PROTOCOL.md and vendor-stacks.md together.
- tools: the client had no scan or GATT listing; added read-only tools/ble_survey.py (macOS untested by me, run on Linux container only for syntax). Add it to README and setup_tools.
- Skills and tools are untested end to end on a real target; run the benchmark in README.md and record gaps here.
- `tools/setup_tools.py` pins jadx and apktool versions and verifies SHA-256 only when `JADX_SHA256`/`APKTOOL_SHA256` are set (it prints the computed hashes); the JDK is the latest 17. Pin real hashes once a machine with github access has downloaded them.
- Windows is untested locally: CI covers `rebuild_analysis.py` and `setup_tools.py`, but the fake-jadx tests skip there and a real run on Windows has not happened. macOS is likewise untested locally (the JDK bundle layout is unit tested).
- The ipa and firmware kinds of `rebuild_analysis.py` verify the hash only.
- Cloud sessions: apkpure, adoptium and github release hosts are blocked unless the environment allows them (README, AGENTS.md).
- iOS, desktop and firmware notes in the skills are thin.
- Vendor stack UUIDs and white-label rows in `re-watch-targets/references/vendor-stacks.md` now carry public sources from an external review, but nobody here has read those sources; check them on the first target that uses each stack.
- The unicorn harness does not apply relocations; add R_AARCH64_RELATIVE handling the first time a real library needs it, with a test.
- `tools/scrub_capture.py` matches `--mask` hex at any nibble offset; a match straddling a byte boundary would mask the wrong nibbles. Rare; align to even offsets if it bites.
