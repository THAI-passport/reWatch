## Summary
`NotifyWriteUtils.dataHandle` dispatches 11 primary command branches (0x05, 0x08, 0x09, 0x0C, 0x0E, 0x0F, 0x11, 0x12, 0x13, 0x14, 0x19, 0x1A, 0x1B).
Upon verifying the additive checksum over the full DF frame, the app sends an FD ACK immediately (`AckPackageConfigUtils.configAck(cmd, key, 0, 1)`) via `write()` before calling any handler.
The core's `Session.onCommand` currently emits a bond prompt on unsolicited `0x0E key 1`, which breaks normal sessions; this must be changed to cache the Classic MAC without prompting unless unprompted pairing is enabled.
Handlers for bind status (0x0C key 8/9), camera shutter (0x0C key 2), and feature updates (0x19) are mapped with proposed core behaviors.

## Proposed changes
### Docs (exact text, target file and section)
In `targets/c900/PROTOCOL.md` section 7.1, add explicit entries for:
- `0x0C key 2`: camera shutter event (`DeviceContro.PHOTO`).
- `0x0E key 1`: watch sends classic Bluetooth MAC address (6 bytes); sent unsolicited after sport history sync (latency 76-80 ms [H]).
- `0x19`: watch feature bitmask broadcast (identical layout to 0x2A28 characteristic read).

### Kotlin core (what, why, test that would catch it)
In `client/c900-android/core/src/main/kotlin/rewatch/c900/Session.kt`:
- Separate `0x0E key 1` from `0x0C key 19` in `onCommand`.
- For `0x0E key 1`: store `classicMac = c.payload.take(6).toByteArray()` instead of automatically returning `Action.AskUserBond`.
- For `0x0C key 9`: return `Action.Fail("bind refused by watch")`.
- Test: Feeding inbound `0x0E key 1` frame does not emit `Action.AskUserBond`.
