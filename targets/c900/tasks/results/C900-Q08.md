# C900-Q08 — Contacts path confirmation (OTA main=4)

Date: 2026-10-13 (Asia/Saigon). Static only (jadx + smali). Status: **done**.

## Answer
Contacts never use a DF command-channel opcode. They are sent as a file over the OTA channel (service 0xFF00, D5/D6 framing) with `OTAUtils(main=4, sub=1)` [C]. No one should invent a DF opcode for contacts.

## Contact file layout (document only) [C, `ContactActivity.saveAsFile`]
The file sent is `MD5(16 bytes) || body`, where MD5 is the digest of `body` (`StringUtils.md5Encode32`, hex-decoded):
- `body[0]` = contact count (u8, wraps above 255); `body[1]` = 0.
- Then `count` 4-byte entries starting at `body[2]`: `off_lo, off_hi, name_len, num_len`. `off` is the cumulative u16 LE offset of this entry's name inside the string area (entry 0 has off 0).
- Then the string area: for each contact, the UTF-8 name followed by the number. `name_len` is in UTF-8 bytes; `num_len` is `String.length()` (characters; equals bytes for digit-only numbers).
- An empty list gives `body = 00` (1 byte).
- Names are cut to at most 30 UTF-8 bytes before this point (`ContactActivity`, two `> 30` checks).
- The file is sent with `main=4`, which skips the final reboot (PROTOCOL §6.3 step 4).
