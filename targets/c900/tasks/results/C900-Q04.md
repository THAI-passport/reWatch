# C900-Q04 — Command-channel key/payload tables (first-contact set)

Date: 2026-10-13 (Asia/Saigon). Static only (jadx + apktool smali of pinned 2.0.1). Status: **done** (acceptance rows all reached; a few argument meanings stay [U], listed at the end).

Builders: `IssuedUtil.getSendByte(cmd, key[, payload])`; sum inserted by `NotifyWriteUtils.write -> addSumCheck` for every frame whose byte 0 is 0xDF. Multi-byte integers are big-endian unless stated.

## 1. Ack timeout and send loop (checked first, smali)
| Claim | Tag | Source |
|---|---|---|
| Ack timeout is **100 s**: `const-wide/32 0x186a0` (100000 ms) | [C] | `NotifyWriteUtils.smali`: `resetTimeout()` and `lambda$new$0` (the send runnable jadx shows as `write`) |
| The timer is armed only for frames with header 0xDF and only while `MainActivity` exists; FD acks the app sends reset the busy flag at once | [C] | same runnable, `b == -33` branch |
| Timeout action: `MBleManager.disconnect()`, clear busy flag | [C] | `lambda$static$1` (`timeoutRun`) |
| Watch FD ack received -> `resetStatus()` (cancel timer, send next queued frame) | [C] | `NotifyWriteUtils.handleAck` |
| Inbound DF with bad sum -> app sends NAK `FD 00 05 sum cmd key 00 03 00` (x=3, status 0) and re-arms 100 s | [C] | `dataHandle` smali: `if-ne` sum -> `:cond_47`, `v11 = 0x3`, `v4 = 0x0` |
| Inbound DF with good sum -> app ACK `FD 00 05 sum cmd key 00 00 01` | [C] | `dataHandle` smali `configAck(v3, v2, v8=0, v9=1)` |
| Write loop: frames <=20 bytes: one write, **no retry**. Longer frames: 20-byte pieces, each full piece up to 2 retries 100 ms apart, 20 ms between pieces; the final remainder piece gets **one** retry after 20 ms. A failed write -> `restAll()` + immediate timeout (disconnect) | [C] | smali `const/16 0x14`, `const-wide/16 0x64`, `const-wide/16 0x14` in the send runnable |
| `write()` is a no-op while `isOTA` is set (command channel paused during OTA) | [C] | `NotifyWriteUtils.write` |

## 2. Frame byte 4 is a protocol version, not a constant
`getSendByte` writes `IssuedUtil.PROTOCOL_VERSION` (static, default `0x01`) at frame index 4 (after the sum is inserted; PROTOCOL §4's "01"). It is overwritten on connect from the 0x2A27 read: strip a leading `V`/`v`, keep the integer before the first `.` [C, `NotifyWriteUtils.onRead`]. Exception: `SettingIssuedUtils.setAutoUpdate` is a hand-built literal frame that always uses `01` [C smali]. Most watches will report major version 1 [I]; the C900 value is [U] (HW-2 0x180A read).

## Contradictions and corrections
- PROTOCOL §4 called byte 4 a fixed `01`; it is `PROTOCOL_VERSION` (default 1, set from 0x2A27). Recorded in FACTS. `client/c900/frames.FIXED_BYTE` comment is therefore incomplete; client code not changed (Phase 3).
- PROTOCOL §3 said "two 100 ms retries per piece"; true only for full 20-byte pieces (see §1).
- PROTOCOL §4 said app acks use x = 0; true for ACK, but the NAK uses x = 3.
- `client/c900/frames.ack()` (SimWatch's watch ack) uses x = `00 01`; the watch's real x is [U] (app reads only bytes 4, 5, 8), so that value is [I], not [C].
- jadx mislabels: language vs exit-find-phone (0x1A/21), `GET_FUNTION`/`CHATGPT_ID` as keys, `BaseResp.CODE_ERROR_PARAMS` for -2000.
