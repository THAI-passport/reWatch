# C900-Q16: cmd 5 health field maps

Date: 2026-10-13 (Asia/Saigon). Gate: static (approved Phase 1c). Sources: box jadx tree + apktool smali (`smali_classes2`), Hiwear Plus 2.0.1. Every offset, stride, mask and bound below was checked in smali; nothing was run.

## Common rules [C smali]
- `HealthUtils.analusis` passes `p = frame[9 : 9 + (len - 5)]` (the payload) to each parser; offsets below are payload offsets (frame offset = p + 9).
- Multi-byte integers use `HexUtil.byte2IntLR`, which is **big-endian** in argument order (INVARIANTS I-34). Single bytes via `byte2IntLR(b)` are unsigned; bytes read raw (marked "signed") are Java signed bytes.
- **Date (2 bytes)** `DevBaseDataUtils.getDateBean` (smali `and-int/lit8 0x7f`, `shr 1`, `shl 3`, `and 0xe0`, `shr 5`, `and 0x1f`; `DevDateBean.getFormatDate` adds `0x7d0`):
  `year = 2000 + ((b0 & 0x7F) >> 1)`, `month = ((b0 & 1) << 3) | (b1 >> 5)`, `day = b1 & 0x1F`. Note: this is **not** the cmd 2 key 1 time packing (I-21).
- **Seconds of day (u32 BE)** -> `hh = s / 3600` (`div-int/lit16 0xe10`), `mm = (s / 60) % 60`, `ss = s % 60`.
- Lists: `count = p[3]`, records start at `p[4]`, fixed stride; `p[2]` is not read by these parsers [C, unread].
- Units are not stated in code for distance and calorie: [U] (no display code read).

## Key 2: steps per hour, `StepUtils.getSportBy1Hour`
| Offset | Width | Meaning | Tag |
|---|---|---|---|
| 0 | 2 | date | [C smali] |
| 2 + 8i (i = 0..23, fixed 24 records, `const/16 0x18`) | 2 BE | steps | [C smali] |
| 4 + 8i | 2 BE | distance (unit [U]) | [C smali] |
| 6 + 8i | 4 BE | calorie (unit [U]) | [C smali] |
Payload length 194. Record i covers hour i (`timeOffset = 4i`, quarter-hours). steps `0xFFFF` -> no data (all three set to -1). steps > 20000 (`0x4e20`) -> steps = distance = 20000, calorie = **400000** (`const v11, 0x61a80`; jadx printed `JCameraView.MEDIA_QUALITY_FUNNY`, a substituted constant, I-24).
Synthetic example (made up): 07:00-08:00 = 1200 steps, 850, 45; other hours `ffff`:
`p = 354d` + 7 x `ffff000000000000` + `04b003520000002d` + 16 x `ffff000000000000` (date 2026-10-13 = `354d`).

## Key 5: blood pressure, `DevBaseDataUtils.getBloodBean`
| Offset | Width | Meaning | Tag |
|---|---|---|---|
| 0 | 2 | date | [C smali] |
| 3 | 1 | count n | [C smali] |
| 4 + 8i | 4 BE | seconds of day | [C smali] |
| 8 + 8i .. 9 + 8i | 2 | not read | [C, unread] |
| 10 + 8i | 1 | systolic; kept if 50..300 (`0x32`, `0x12c`) | [C smali] |

Note: as a u8 the systolic can never exceed 255, so the 300 bound is never hit. Synthetic: `354d 00 01 00006978 0100 76 4c` = 07:30:00, 118/76.

## Key 9: sleep summary, `SleepUtils.receiveTotalSleepData`
| Offset | Width | Meaning | Tag |
|---|---|---|---|
| 0 | 2 | date | [C smali] |
| 2 | 2 BE | start offset (minutes; same scale as the 0..1439 checks) | [C smali; unit [I]] |
| 4 | 2 BE | light minutes | [C smali] |
| 6 | 2 BE | deep minutes | [C smali] |
| 8 | 2 BE | end offset | [C smali] |
| 10 | 2 BE | awake minutes | [C smali] |
Light, deep or awake > 1439 (`0x59f`) -> all three set to 0. Not a list. (`SleepUtils.getSleepMinuteData`, 4-byte records `u16 offset, -, mode & 0xF`, exists but is not reached from key 9.) Synthetic: `354d 0564 00f0 0078 01a4 000f` = start 1380 (23:00), light 240, deep 120, end 420 (07:00), awake 15.

## Key 12: total steps today, `StepUtils.getTotalStepData`
| Offset | Width | Meaning | Tag |
|---|---|---|---|
| 0 | 4 BE | steps | [C smali] |
| 4 | 4 BE | distance (unit [U]) | [C smali] |
| 8 | 4 BE | calorie (unit [U]) | [C smali] |
No date: the app stamps the phone's date. If steps > 240000 (`0x3a980`) or distance > 192000 (`0x2ee00`) or calorie > 4464000 (`0x441d80`), all three are 0. Synthetic: `00001f40 000015e0 00000140` = 8000, 5600, 320.

## Key 15: sport sessions, `DevBaseDataUtils.getSportModeData`
| Offset in record (record = 4 + 30i, stride 30 `0x1e`) | Width | Meaning | Tag |
|---|---|---|---|
| 0 | 4 BE | start, seconds of day | [C smali] |
| 4 | 4 BE | end | [C smali] |
| 8 | 4 BE | duration (seconds [I]) | [C smali] |
| 12 | 1 signed | mode: 0 run, 1 rope skipping, 2 sit-ups, 3 cycling (from the "last ... data" keys it saves) | [C smali] |
| 13 | 1 signed | heart rate; raw signed byte, so > 127 bpm reads negative in the app | [C smali] |
| 14 | 4 BE | calorie | [C smali] |
| 18 / 22 / 26 | 4 BE each | modeData1 / 2 / 3 (meaning per mode [U]) | [C smali] |
Payload header: date `p[0..1]`, count `p[3]`. No validity bounds. Synthetic: `354d 00 01` + `00006978 00007080 00000708 00 78 000000fa 00000bb8 00000000 00000000` = run 07:30:00-08:00:00, 1800 s, HR 120, calorie 250, modeData1 3000.

## Key 14 (from C900-Q14, for completeness)
SpO2 inline in `analusis`: `p[0..1]` date, `p[4..7]` u32 seconds of day, `p[11]` percent.

## Contradictions and new quirks
- None with FACTS. New jadx constant substitution: `JCameraView.MEDIA_QUALITY_FUNNY` = 400000 in `getSportBy1Hour` (added to INVARIANTS I-24).
- The health date packing differs from the time-sync packing (new INVARIANTS I-36).

## Still [U]
Units of distance and calorie; meaning of the type byte (HR, temperature); modeData1-3 per mode; `p[2]` in list headers; bytes 9-10 of HR records and 8-9 of BP records.
