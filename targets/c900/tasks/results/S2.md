# S2 — Audit PROTOCOL claims (smali)

Date: 2026-10-13 (Asia/Saigon). Static only.

## Questions
1. Is the time-sync year offset really -2000, or a jadx substitution artifact?
2. Do the frame vectors in PROTOCOL section 9 match the codec?

## Method
- `apktool d -r -f` of the base APK into `work/smali` (smali needed; earlier `-s` tree had none).
- Read `SettingIssuedUtils.settingSysTime` and `CommandID` fields in smali.
- Ran `tests/test_c900_frames.py` vectors against the updated codec.

## Findings
- Year offset confirmed: `add-int/lit16 v2, v2, -0x7d0` [C]. Jadx had printed `BaseResp.CODE_ERROR_PARAMS` (-2000) in place of the literal.
- Packing bytes match the bit layout already in PROTOCOL; implemented as `frames.time_payload`.
- Settings-query vector `df0005ee0901000000` still green; time packing vector `6a9ae15e` for 2026-10-13 14:05:30 added.
- CommandID.smali values match the PROTOCOL table (OTA 1, SETTING 2, BIND 3, UNBIND 4, RESET 6, FACTORY_TEST 7, DEVICE_SETTING 9, WATCH_FACE 0x0F, OTA_NEW 0x13, RESTORE 0x0D).

## Outcome
PROTOCOL section 5 updated; FACTS section 4; S2 done. No hardware.
