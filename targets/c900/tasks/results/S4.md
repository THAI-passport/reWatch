# S4 — Firmware / watch-face transfer path (read only)

Date: 2026-10-13 (Asia/Saigon). Static only. No OTA bytes sent.

## Scope
Document the watch-face file format and the OTA-channel transfer framing. Never install, never write to a watch.

## Findings (summary; full text in PROTOCOL.md section 6)
- Store dial `.bin` is obfuscated Base64 text (`StringUtils.decodeInfo` + Base64), optionally trimmed from a header length field, then pushed with `OTAUtils(main=5, sub=1)`.
- DIY background: `ParTool.rawToPar(..., false,false,false)` -> PAR blob -> `OTAUtils(main=2, sub=1)`.
- OTA channel (service 0xFF00): control `D5 main sub fun 00 00 plen[2] payload sum`; data `D6` + chunk. CRC poly 0x31 (left-shift). Ready reply fun 0x81 carries MTU / interval / groupPacNum / timeout.
- Cus5610 on 0x18A8 is a separate DFU path; dial push does not use it.
- PAR container layout remains [U] (native lib). Client must not send any of this without a reviewed design and owner approval.
