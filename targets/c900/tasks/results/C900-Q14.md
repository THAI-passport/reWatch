## Step 3 — cmd 0x0F face replies (`BleDataUtils.handleWatchFaceInfo` + dispatcher) [C jadx]
Payload `p` from frame byte 9. Code width `w` = 8 if feature `is8Bytes` (b18 0x40), else 2.
| key | Fields |
|---|---|
| 2 (and 9, same layout) | `p[0]` face count n; `p[1..w]` current face code; then n codes of w bytes. Default sizes by `deviceResolutionRatio`: 1 -> dial 266240 / paper 118784; 2 -> dial 90112 / paper (library constant, value [U]); >= 16 -> paper u32 BE at `p[-8..-5]`, dial u32 BE at `p[-4..-1]` |
| 5 | custom face: code (w bytes), timeX u16, timeY u16, color u16, aboveTime, belowTime, bgUpdate (same as outbound key 5) |
| 6 / 8 | frame byte 9 = 1 -> custom face / custom dial updated (UI refresh) |
Sync: keys 2, 5, 9 advance the connect sync sequence (Q05).

## Step 4 — FD-ack follow-ups (`BleDataUtils.setSettingSuccess`) [C; smali `xor-int/lit8 0x55`, `const/16 0xa`]
Called from `NotifyWriteUtils.handleAck` only for **cmd 2** acks with **status 1**; argument = ack key (byte 5). Sync = `DataType.SYNCHRONOUS` (connect sync sequence).
| Acked cmd 2 key | Follow-up |
|---|---|
| 1 (time sync), in sync | if feature `isSupportPair` (b15 0x40): **createBond** on the classic address = BLE MAC with the last byte XOR 0x55, only if that device is BOND_NONE (10); then stop (no profile from here). Else if `isBLE3` (b1 0x80): send cmd 0x0E key 3. Else: send profile (key 4) and, if supported, user name (key 36) |
| 3 (step goal), in sync | send settings query (cmd 9 key 0) |
| 4 (profile), in sync | send step goal (key 3) |
| 10 (pairing) | send time sync (key 1) |
| others | no protocol follow-up; UI callback only |
Sync chain from code: bind accept (0x0C/8) -> key 10 -> ack -> time (key 1) -> ack -> bond / 0x0E-3 / profile -> ... -> step goal ack -> cmd 9.

## Step 5 — `MainActivity$4.run` [C smali]
A Runnable on the main screen. Its MAC comes from the `ACTION_CREATE_BOND` broadcast extra `remoteDeviceMac`, sent by `BleDataUtils.handleMountBTInfo` when the watch reports its classic BT MAC on inbound **cmd 0x0E key 1** (6 bytes, not all zero). It: gets that device; if BOND_NONE (10), counts an attempt and calls `createBond()`; then, if still connected, not BONDED (12) and attempts < 3, re-posts itself after **35 s** (`0x88b8`). Needs BLUETOOTH_CONNECT on Android 12+.

## createBond conditions, all three sites
| Site | Trigger | Target address | Condition |
|---|---|---|---|
| `setDeviceContro` | inbound 0x0C key 19 | the connected BLE address | BOND_NONE |
| `setSettingSuccess` | FD ack cmd 2 key 1, status 1, sync mode | BLE MAC, last byte XOR 0x55 | feature b15 0x40 and BOND_NONE |
| `MainActivity$4.run` | inbound 0x0E key 1 (classic MAC) | the reported classic MAC | BOND_NONE; up to 3 tries 35 s apart while not bonded |
So the app never bonds unprompted: each path needs a watch message or a watch feature bit. Whether the C900 sends any of them is [U] (Q03).

## Step 6 — camera shutter, other device-control, battery [C]
`DeviceContro.getDeviceContro` (inbound 0x0C keys not handled inline, forwarded to `BleInfoCallback.callDeviceContro`): 1 find phone, **2 take photo (shutter)**, 3 open camera, 4 close camera, 5 heart test stopped, 6 BP test stopped, 14 temperature test stopped, 16 SpO2 test stopped; others unknown.
Battery: 0x180F/0x2A19 read/notify; value = `byte0 & 0xff` (percent) stored in `BleConstants.battery`. In sync mode, 500 ms later the app sends bind (cmd 3 key 0) [C, `NotifyWriteUtils.onRead`]. So the connect order is: 0x2A27 version -> 0x2A26 firmware -> features -> battery -> bind.

## Step 7 — `readFeatures` byte 25 bit 0x80 [C smali]
Confirmed shared: both `isShowHrAutoTest` and `isShowDnd` read index `v11 = 0x19` (25) with mask `v4 = 0x80` (set once, `const/16 v4, 0x80`); bit set hides both. Not a jadx artefact; vendor reuse. The same method checks byte 0 against `-0x56` (0xAA).
