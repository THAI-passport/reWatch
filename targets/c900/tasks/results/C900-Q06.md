# C900-Q06 — Dial `.bin` decode and header trim (documentation only)

Date: 2026-10-13 (Asia/Saigon). Static only (jadx + smali). Status: **done** (optional test not added; see end).

**Client rule:** document only; no face upload (PROTOCOL §6, PLAN Phase 4, C900-D05). No vendor dial file is in git.

## Decode [C, `utils/StringUtils.decodeInfo` / `decodeInfoToBytes`, smali const-strings]
1. The downloaded `.bin` is read as text and joined into one string.
2. Three 32-hex-char tokens are replaced, in this order: `md5("ZZ22")` -> `=`, `md5("Z22Z")` -> `+`, `md5("XGHJ")` -> `/`. Tokens are lower-case MD5 hex (`md5Encode32` = `MessageDigest("MD5")` hex, then `toLowerCase`). jadx printed the `/` as `FileUriModel.SCHEME`; smali has `const-string "/"`.
3. Trim whitespace, then Android `Base64.decode(..., DEFAULT)` (standard alphabet).
Token seeds re-derived locally (no vendor data): `ZZ22` -> `37396d18...f110`, `Z22Z` -> `f9319252...8abd`, `XGHJ` -> `34657488...062a`; they match PROTOCOL §6.1 [V, local MD5].
The app also has the inverse (`StringUtils` encoder: Base64 encode, then the same three swaps the other way) [C].

## Header trim [C, `DialDetailActivity.getFileBuffer`, smali]
Skipped entirely when `BleDataUtils.binPreviewFlag` is set. That flag is reported **by the watch**: feature byte 18 bit 0x20 (0x2A28 read or cmd 0x19 reply; see C900-Q05) [C].
Otherwise, on the decoded buffer `b`:
- `i = ((b[0x10] & 0xff) - (b[0x11] & 0xff) - 1) * 0x14` (bytes 16 and 17; times 20).
- `n = b[i+22] | b[i+23] << 8 | b[i+24] << 16 | b[i+25] << 24` (u32 little-endian; `HexUtil.byte2IntLR` is big-endian over its argument order and is called with `i+25, i+24, i+23, i+22`).
- If `n >= len(b)` or `n <= 0`, keep the whole buffer; else keep `b[0:n]`. Any exception (for example an index out of range) is caught and the untrimmed buffer is sent.
smali literals: `0x10`, `0x11`, `mul-int/lit8 0x14`, `add-int/lit8 0x16 / 0x17 / 0x18 / 0x19`.
[I] reading: the header holds a table of 20-byte entries, and the u32 at offset 22 of the last-but-one-indexed entry is the payload end; the field meanings are not in the app.

## Which screens trim [C]
| Screen | Push | Trim |
|---|---|---|
| `DialDetailActivity` (store face) | `OTAUtils(5, 1, getFileBuffer(...))` | yes, unless `binPreviewFlag` |
| `OwnerDialDetailActivity` (purchased face) | `OTAUtils(5, 1, decodeInfoToBytes(...))` | **no** |
| `WatchFaceEditActivity` / `WatchFaceTimeEditActivity` (DIY) | `OTAUtils(2, 1, ...)` | no (PAR / decoded data) |
This answers part of PROTOCOL §6.5 "whether every dial.bin uses the trim rule": it depends on the watch's `binPreviewFlag` and on the screen.
