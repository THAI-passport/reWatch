# C900-Q17: notify_log.py OTA-safe subscribe

Date: 2026-10-13 (Asia/Saigon). Gate: static, tool change (approved Phase 1c). Nothing was run against a device.

## Result: done
- `plan(services, only, deny)` picks the characteristics before anything is enabled. A characteristic is skipped if it or its **service** is denied.
- Default deny (always on, also with `--only`): 0xFF00, 0xFF01-0xFF03, 0x18A8, 0x2AA8, 0x2AA9, and any UUID ending `dcca9e`. Short forms are expanded on the Bluetooth base UUID; matching is case-insensitive.
- `--deny UUID` (repeatable) adds to the list. `--only UUID` (repeatable) subscribes to exactly those.
- A denied UUID in `--only` makes the CLI exit **2** before connecting; the library raises `DeniedUUID` before any `start_notify`.
- Prints `will subscribe to N characteristic(s): ...` before listening.
- No other behaviour change: same output lines, masking, JSON, stop_notify.

## Evidence
- `tools/notify_log.py` (docstring updated), `README.md` tool row, `FIXES.md` (moved Open -> Fixed), INVARIANTS I-50 rewritten with the new evidence, HW-0-RUNSHEET §0/§2b point at `--only`.

## Tests (`tests/test_notify_log.py`, fake C900 GATT table)
- default run subscribes only command `...0003`, battery and an unrelated char; no OTA char gets a handler;
- `--only` (upper-case input) subscribes exactly one;
- denied UUID in `only` raises before any subscribe;
- CLI returns 2 for `--only` with 0xFF03 (upper-case full), `...dcca9e`, and short `2aa9`;
- `--deny` applies without `--only`;
- the plan line is announced first.
