# C900-Q18: capture decoder and synthetic fixture dry run

Date: 2026-10-13 (Asia/Saigon). Gate: static, tool change (approved Phase 1c). Decode only: the script never connects, sends or replays.

## Result: done
`tools/c900_decode.py` (stdlib; uses `tools/btcap.py` as a library, unchanged):
- input: a btsnoop/pcap/pcapng capture, or `btcap.py --json` output (JSON lacks reads, so no 0x2A2x values from it);
- keeps the write `...0002` and notify `...0003` characteristics (`--write-uuid/--notify-uuid` or `--write-handle/--notify-handle` when discovery was not captured);
- reassembles DF/FD frames to `len + 4` per direction, checks the sum (PROTOCOL §4), checks `plen`;
- labels cmd/key from PROTOCOL §5/§7 names only;
- flags app-side blocked cmds (I-20) and any PDU on OTA/DFU characteristics (counted, never decoded; this is Q19's stop condition);
- pairs ATT read requests/responses itself (btcap lists writes and notifies only) to show 0x2A27, 0x2A26, 0x2A28 (feature bits b1 0x80, b15 0x40, b18 0x20, b25 0x80, marker 0xAA) and 0x2A19 (percent); cmd 0x19 replies are decoded the same way;
- summary block: frame counts, bad sums, stray chunks, version byte(s) seen, 0x2A27/0x2A26, features, battery, bond triggers yes/no (0x0C/19, 0x0E/1, b15 0x40), blocked cmds yes/no, OTA traffic yes/no;
- privacy: cmd 2 key 18 text hidden unless `--show-text`; the 0x0E key 1 MAC is always masked to the last two octets.
