# S-21 and S-22: unknown services and the QR payload (static, 2026-10-13)

Artifact: pinned Hiwear Plus 2.0.1 base APK from `resources/c900` (LFS), inner APK SHA-256 prefix `931efc77` matches SOURCES `INNER_SHA256`. Tool: androguard 4 (PyPI) in a scratch venv; jadx/apktool could not be installed (GitHub release host blocked from the cloud session). Three dex files, 198k strings. Nothing from the APK was committed.

## S-21: 0xFF10 / 0xFF12 (chars FFF1, FF13, FF14) [C, negative]
- No string in any dex contains `ff10`, `ff12`, `fff1`, `ff13` or `ff14` (case-insensitive), in full-UUID or short form. The app's UUID strings cover 0xFF00-0xFF03, 0x18A8, 0x2AA8/9, the NUS pair, 0x180A/0x180F and standard SIG tables only.
- No UUID format string (`0000%04x-...`) exists that could build them at runtime.
- Reading: the app never touches 0xFF10/0xFF12. They come from the watch firmware for another client (likely a vendor test or an audio/other profile) [I]. The probe keeps them denied; the open client must not use them.
- Limits: native libraries (`config.arm64_v8a.apk`) were not searched; they handle images (abpartool), not BLE [C, PROTOCOL section 1].

## S-22: what the QR code carries [C]
`ScanCodeActivity.onResultBack` returns the decoded text as extra `scanResult`; `BleScanActivity.onActivityResult` (request 1002) parses it:
1. Text starts with `LE` and is longer than 20 characters: the MAC is characters 3..19 (17 characters, `XX:XX:XX:XX:XX:XX`).
2. Otherwise, text containing `?para=`: everything after `?para=`.
3. The result must be exactly 17 characters; then `MBleManager.connect(mac)` is called. Otherwise a "not found" toast.

So the QR is only the watch's BLE address in a wrapper (`LE` prefix or a URL with `?para=`). No key, token or name is read from it. The owner's observation (OWNER-QR-2026-10-13) is explained: the QR skips the scan list and connects straight to that address; binding is still cmd 3 key 0 after connect.

Client consequence: an optional QR reader that applies the same two rules and accepts only a 17-character MAC is enough; scanning by name `Watch Ultra` plus the MAC + `12 34` scan record works without it.
